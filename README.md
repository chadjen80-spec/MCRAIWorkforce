# MCR AI Workforce

Hybrid multi-agent AI automation platform for **MCR SME Copilot** (MCR Technology, a business unit of
Mercurialz Media & Game). A business owner submits one master command; six specialised agents plan it,
produce the deliverables on background queues, verify them and ask for human approval.

```
Dashboard (Next.js) ──► FastAPI gateway ──► auth + organization context
                                 │
                                 ▼
        Planner agent ─► task dependency graph ─► PostgreSQL (source of truth)
                                 │
                 Redis/Celery queues: planner · content · image · document · video · qa
                                 │
        Hybrid router: cloud LLM / local ComfyUI GPU / local CPU / local FFmpeg
                                 │
        QA agent (PASS · REVISE · HUMAN_REVIEW) ─► human approval ─► S3/MinIO artifacts
```

n8n is the integration layer (webhook in, notifications out). It never holds job state and never
runs long synchronous requests: it submits a job, then polls.

## What is in the repository

| Path | Contents |
|---|---|
| `apps/api` | FastAPI app, SQLAlchemy models, Alembic migration, Celery workers, the six agents, provider adapters, tests |
| `apps/web` | Next.js dashboard (TypeScript, Tailwind, Thai/English) |
| `n8n/workflows/mcr-ai-workforce.json` | Importable workflow (generated by `n8n/build_workflow.py`) |
| `infrastructure/docker` | Dockerfiles and the production Caddyfile |
| `compose.yaml`, `compose.prod.yaml` | Development stack and production overrides |
| `scripts/e2e_acceptance.py` | End-to-end acceptance check against a running stack |
| `docs/` | API reference, Windows install, GPU worker, n8n, testing, production checklist, limitations |

The six agents live in one Python package (`apps/api/app/agents`) and share one image; each Celery
worker process subscribes to its own queue(s). Separate top-level `workers/*` packages would only
have duplicated the models and orchestration code.

## Quick start

Two ways to run it. Both are described step by step in [docs/INSTALL_WINDOWS.md](docs/INSTALL_WINDOWS.md).

1. **Docker Compose (full stack: PostgreSQL, Redis, MinIO, n8n):** copy `.env.example` to `.env`,
   fill in the secrets, `docker compose up -d --build`, open http://localhost:3000.
2. **No Docker (single machine, SQLite + filesystem broker + local files):** needs only `uv` and
   Node.js. Good for development and for trying the system on a laptop.

## Agents and where their prompts/adapters are

| Agent | Code | Does | Provider routing |
|---|---|---|---|
| Planner | `agents/planner.py` | Command → validated deliverable spec → deterministic task graph, cost estimate, budget check | Cloud LLM; deterministic rule parser when no LLM is configured or permitted |
| Content | `agents/content.py` | Captions, hashtags, CTAs, YouTube title/description, campaign brief (TH/EN) | Cloud LLM |
| Image | `agents/image.py` | Real PNG files, cropped to the requested aspect ratio | Local ComfyUI → authorised cloud fallback |
| Document | `agents/document.py` | Proposal / quotation / brief / report as PDF (ReportLab) and DOCX (python-docx) from templates | Cloud LLM for body text, local CPU for rendering |
| Video | `agents/video.py` | Script, storyboard, SRT, scene manifest, optional voiceover, 1080p H.264/AAC MP4 | Cloud LLM + TTS, local FFmpeg |
| QA | `agents/qa.py` | Checksums, file integrity, counts, language, codecs/duration, licensing metadata, optional LLM text review | Local CPU + cloud LLM |

Prompts: `apps/api/app/agents/prompts.py`. Adapters: `apps/api/app/providers/` (OpenAI-compatible
HTTP, ComfyUI HTTP). Routing and budget enforcement: `apps/api/app/services/router.py`.

## Honesty rules built into the system

- A job is `completed` only when every deliverable task succeeded **and** QA verified the stored files.
- Without an AI provider, tasks **fail** with `PROVIDER_NOT_CONFIGURED`. Placeholder output exists only
  when `DEMO_MODE=true` is set explicitly; such files are flagged `is_demo`, watermarked, shown with a
  DEMO badge and always escalated to human review. Demo mode cannot be enabled in production.
- The Document agent never writes prices or legal terms: those sections come from fixed templates
  that say they must be supplied by the company.
- If text-to-speech is unavailable the video gets a silent audio track and the limitation is
  recorded in the artifact metadata and in the QA report.
